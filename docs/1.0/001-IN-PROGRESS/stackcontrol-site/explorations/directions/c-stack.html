// the lifecycle

Five phases. One stack.

deskwork treats a feature as a stack of phases. Each one has a slash command, a defined output, and a hand-off to the next. Work moves down the stack — never sideways into chaos.

01
/dw-lifecycle:define

Define

An interview captures the problem, the scope, and the non-goals before a line is written. Scope discovery runs automatically to surface the surfaces you'd have missed.

02
/dw-lifecycle:setup · :issues

Workplan

The feature becomes a versioned PRD and a phased workplan, then fans out into a parent issue plus one GitHub issue per phase — links back-filled into the plan.

03
/dw-lifecycle:implement

Implement

Walk the workplan task by task, delegating each to the right subagent, committing at task boundaries. Scope-widen runs between tasks to catch drift early.

04
/dw-lifecycle:audit-barrage

Audit

Fire claude, codex, and gemini in parallel against the diff. Cross-model findings land in a durable audit log and get promoted back into the plan.

05
/dw-lifecycle:ship

Ship

Verify acceptance criteria, open the PR, and stop at the boundary — the operator owns the merge. Then :complete archives the docs and closes the issues.

// the shape of it

What it is, why it exists, how it runs.

What

A lifecycle plugin for Claude Code

Slash commands that carry a feature from a one-line idea to a merged PR — with workplans, scope discovery, audit barrages, and an editorial pipeline all in the same toolchain.

Why

Agentic work needs rails

Subagents are fast and forgetful. deskwork imposes phases, commit boundaries, and cross-model review so the speed doesn't turn into a pile of plausible-looking debt.

How

Orchestration, not autopilot

The operator drives. Each phase delegates to specialized subagents, writes its output to disk, and hands off — so you can inspect, correct, and resume at any boundary.
